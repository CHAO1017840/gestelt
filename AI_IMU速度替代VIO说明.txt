AI_IMU 修正 IMU + 速度观测接入 PX4 说明
========================================
更新时间：2026-11-04
适用环境：Ubuntu 22.04 + ROS 2 Humble
功能分支：feature/ai-imu-ros2
最新提交：d0ddbb7 Add experimental AI IMU velocity estimator


一、先明确“替代 VIO”的含义
----------------------------
当前方案不是用一个噪声协方差直接替代 VIO。

AI_IMU 模型输出：
  1. 修正后的加速度
  2. 修正后的角速度
  3. 加速度噪声/方差
  4. 角速度噪声/方差

速度节点使用修正后的加速度和角速度做捷联积分：

  角速度 -> 姿态积分
  加速度 -> 去重力 -> 世界坐标系速度积分

最终只向 PX4 提供速度观测，不提供可信位置。

因此这是“速度-only 外部导航”，不是完整 VIO。
长期运行会漂移，不能直接用于未经测试的实机自主飞行。


二、数据流
----------
原始 IMU：
  /drone0/mavros/imu/data_raw
  sensor_msgs/msg/Imu

AI 修正：
  /drone0/mavros/ai/imu_corrected
  sensor_msgs/msg/Imu

AI 噪声输出，可选监控：
  /drone0/mavros/ai/imu_noise
  ai_msgs/msg/ImuNoise

速度估计：
  /drone0/mavros/odometry/out
  nav_msgs/msg/Odometry

兼容速度话题：
  /drone0/ai_imu/velocity
  geometry_msgs/msg/Vector3Stamped

MAVROS 将 /mavros/odometry/out 转换为 MAVLink ODOMETRY，
PX4 再将其作为外部速度观测送入 EKF2。


三、构建
--------
终端执行：

  cd /home/cjc/ws_capstone/gestelt
  source /opt/ros/humble/setup.bash

  python3 -m pip install --user -r \
    imu_listener_pkg/requirements.txt

  colcon build --symlink-install \
    --packages-select ai_msgs imu_listener_pkg

  source install/setup.bash

检查 ONNX Runtime：

  python3 -c \
    "import onnxruntime, numpy; \
     print(onnxruntime.__version__, numpy.__version__)"

注意：
  - 如果现有 NumPy 已经满足依赖，不要盲目升级或降级。
  - 当前环境已经验证 NumPy 1.26.4 和 2.2.6。
  - 某些 ROS 包依赖 NumPy 1.x ABI，较新的 OpenCV 又可能要求 NumPy 2.x。


四、PX4 设置
------------
本方案不使用 iris_vision 的 VIO 输出。建议先使用普通 iris SITL：

  cd /home/cjc/ws_capstone/PX4-Autopilot
  make px4_sitl gazebo-classic_iris

等待：

  Ready for takeoff!

在 PX4 的 pxh> 终端执行：

  param set EKF2_EV_CTRL 4
  param set EKF2_GPS_CTRL 0
  param set EKF2_HGT_REF 0
  param save

参数含义：

  EKF2_EV_CTRL=4
    只使用外部 3D 速度观测。

  EKF2_GPS_CTRL=0
    不融合 GPS。

  EKF2_HGT_REF=0
    高度参考使用气压计。

EKF2_HGT_REF 是重启生效参数。保存参数后应重启 PX4。

如需测试故障保护：

  param set SYS_FAILURE_EN 1


五、启动 Gestelt、MAVROS 和 AI_IMU 速度节点
-------------------------------------------
终端 2：

  cd /home/cjc/ws_capstone/gestelt
  source /opt/ros/humble/setup.bash
  source install/setup.bash

  ros2 launch gestelt_bringup scenario_ros2.launch.py \
    scenario:=empty_map \
    run_mission:=false \
    use_rviz:=true \
    use_gazebo:=false \
    use_fake_drone:=false \
    use_mavros:=true \
    use_ai_imu:=true \
    use_ai_imu_velocity:=true \
    ai_imu_inference_stride:=1 \
    enforce_gps_off:=true

关键参数：

  use_ai_imu:=true
    启动 AI_IMU ONNX 修正节点。

  use_ai_imu_velocity:=true
    启动修正 IMU 速度节点。

  ai_imu_inference_stride:=1
    每帧都推理。当前机器约 1 ms/次，可接近 200 Hz。

  use_mavros:=true
    启动 MAVROS。速度 ODOMETRY 需要 MAVROS。

  enforce_gps_off:=true
    自动设置 EKF2_GPS_CTRL=0 并阻断 HIL_GPS。

不要同时设置：

  use_ai_velocity:=true

因为 use_ai_velocity 会启动另一个速度桥接节点，
造成两个发布者同时写 /drone0/mavros/odometry/out。

如果只启动 AI_IMU 包，也可以直接运行：

  ros2 launch imu_listener_pkg ai_imu_ros2.launch.py \
    namespace:=drone0 \
    enable_velocity_estimator:=true \
    inference_stride:=1


六、静止校准
------------
速度节点默认要求 200 个修正 IMU 样本用于静态校准：

  ai_imu_velocity_initialization_samples=200

校准内容：

  - 修正陀螺零偏
  - 修正残余重力/加速度偏置

校准期间速度保持为零。

输出频率约 200 Hz 时：
  200 个样本约 1 秒

默认推理 stride=5、输出约 40 Hz 时：
  200 个样本约 5 秒

启动条件：

  - 无人机必须静止。
  - 无人机必须水平放置。
  - 当前姿态积分从 identity 姿态开始。
  - 初始 yaw 无法仅靠加速度观测确定。

校准完成日志应出现：

  Stationary calibration complete: gyro_bias=[...]

校准完成前不要起飞。


七、检查 AI 修正数据
--------------------
检查修正 IMU：

  ros2 topic echo --once \
    /drone0/mavros/ai/imu_corrected

检查频率：

  ros2 topic hz /drone0/mavros/ai/imu_corrected

静止、水平放置时，修正后的加速度应接近：

  linear_acceleration:
    x: 接近 0
    y: 接近 0
    z: 接近 +9.81

注意：
  模型只有在 200 帧窗口填满后才发布修正 IMU。
  因此启动后不会立即出现 /mavros/ai/imu_corrected。


八、检查速度输出
----------------
只看线性速度：

  ros2 topic echo --once \
    /drone0/mavros/odometry/out \
    --field twist.twist.linear

检查频率：

  ros2 topic hz /drone0/mavros/odometry/out

检查兼容速度话题：

  ros2 topic echo --once /drone0/ai_imu/velocity
  ros2 topic hz /drone0/ai_imu/velocity

静止校准后的静止状态应接近：

  x: 0
  y: 0
  z: 0

Odometry 中：

  pose.position 为 NaN
  pose.covariance 很大
  twist.twist.linear 是有效速度
  twist.covariance 是速度协方差

这意味着 PX4 只能使用速度，不应把 pose 当成位置。


九、检查 MAVROS 和 PX4
----------------------
检查 MAVROS 输出：

  ros2 topic hz /drone0/mavros/odometry/out
  ros2 topic echo --once /drone0/mavros/odometry/out

在 PX4 pxh> 检查：

  listener estimator_status_flags
  listener vehicle_local_position
  listener vehicle_visual_odometry

重点确认：

  cs_gps: False
  cs_gps_hgt: False
  cs_ev_vel: True

没有 VIO 位置时，不要期待长期稳定的：

  cs_ev_pos: True
  cs_ev_hgt: True

速度-only 方案缺少绝对位置修正，因此位置会随时间漂移。


十、先起飞、中途失效的测试方法
--------------------------------
目标流程：

  VIO/GPS 正常
    -> 正常起飞
    -> AI_IMU 以“影子模式”运行
    -> 用 VIO/GPS 检查 AI 速度误差
    -> 悬停时准备接管
    -> 注入 VIO/GPS 失效
    -> AI 速度成为速度观测
    -> 立即观察 EKF2
    -> 短时间测试后主动降落

重要限制：

  当前分支还不支持自动“影子模式 + 中途切换”。
  use_ai_imu_velocity:=true 会从启动开始直接发布
  /drone0/mavros/odometry/out，无法在飞行中按条件启用。

  当前速度节点也没有使用 VIO/GPS 健康时的速度作为参考
  进行在线偏置校准。

  因此，下面 10.1 节可以在当前代码上测试。
  10.2 和 10.3 节描述完整接管验收流程，必须先实现速度源仲裁和
  健康参考校准，不能把当前节点直接当作已完成的中途接管系统。


10.1 当前可执行的影子测试
-------------------------
第一步：PX4 使用 VIO 正常运行。

  cd /home/cjc/ws_capstone/PX4-Autopilot
  make px4_sitl gazebo-classic_iris_vision

第二步：启动 Gestelt、VIO 和 MAVROS，但不把 AI 速度送入 PX4。

  cd /home/cjc/ws_capstone/gestelt
  source /opt/ros/humble/setup.bash
  source install/setup.bash

  ros2 launch gestelt_bringup scenario_ros2.launch.py \
    scenario:=empty_map \
    run_mission:=false \
    use_gazebo:=false \
    use_fake_drone:=false \
    use_mavros:=true \
    use_ai_imu:=true \
    use_ai_imu_velocity:=false \
    enforce_gps_off:=true

第三步：在起飞前启动 AI 速度影子节点。

  ros2 run imu_listener_pkg ai_imu_velocity.py \
    --ros-args \
    -r __ns:=/drone0 \
    -p corrected_imu_topic:=mavros/ai/imu_corrected \
    -p output_topic:=ai_imu/debug_odometry \
    -p velocity_topic:=ai_imu/velocity \
    -p initialization_samples:=200

输出分别进入：

  /drone0/ai_imu/debug_odometry
  /drone0/ai_imu/velocity

不会进入：

  /drone0/mavros/odometry/out

因此不会直接污染 PX4 EKF2。

必须在起飞前保持静止，等待：

  Stationary calibration complete: gyro_bias=[...]

第四步：用 VIO 起飞并悬停。

  python3 \
    "$(ros2 pkg prefix gestelt_bringup)/share/gestelt_bringup/scenarios/empty_map.py"

第五步：比较 AI 影子速度和 PX4/VIO 速度。

  ros2 topic echo --once /drone0/ai_imu/velocity
  ros2 topic echo --once \
    /drone0/mavros/local_position/velocity_local

建议至少持续观察 30 至 60 秒。

影子测试验收条件建议：

  - 静止 60 秒，AI 速度模长小于 0.1 m/s
  - 悬停时，水平速度误差小于 0.3 m/s
  - 悬停时，垂直速度误差小于 0.2 m/s
  - x/y/z 正负号一致
  - 无 NaN/Inf
  - 无持续增长的偏置

任何一个条件不满足，都不能进入中途接管测试。

当前模型在 Gazebo iris 上曾经出现：

  静止速度漂移超过 20 m/s
  High Accelerometer Bias
  height estimate unstable
  velocity estimate error
  pre_flight_checks_pass = 0

因此必须先解决模型与仿真 IMU 的域匹配问题。


10.2 正式接管测试的前置条件
----------------------------
以下“集成到场景自动运行”的功能尚未实现：

  1. 自动启动、监控和记录 AI 影子速度
  2. VIO/GPS 健康参考速度校准
  3. 速度源仲裁器
  4. 接管误差门限
  5. 接管失败自动退出
  6. VIO/GPS 恢复后的平滑切回

不能通过给 /drone0/mavros/odometry/out 启动第二个发布者来完成切换。
VIO 和 AI 同时写同一话题会造成来源竞争。

应增加一个唯一的速度源仲裁节点：

  VIO/GPS 健康
    -> 只转发 VIO/GPS 观测

  AI 健康且参考误差合格
    -> 转发 AI 速度影子数据

  来源不健康
    -> 停止转发并触发降落


10.3 实现后的完整测试顺序
--------------------------
1. 地面静止
   - 启动 AI_IMU 修正
   - 完成影子速度节点校准
   - 确认静止速度稳定

2. VIO/GPS 正常起飞
   - 正常悬停
   - AI 影子节点持续运行
   - 不把 AI 速度发送给 PX4

3. 健康参考校准
   - 使用 PX4 或 VIO 速度估计 AI 加速度/姿态偏差
   - 比较 AI 速度与参考速度
   - 设定接管门限

4. 悬停准备
   - 保持位置悬停
   - 确认 AI 速度误差在门限内
   - 记录当前 EKF2 状态

5. 先准备 AI 速度源
   - 由仲裁节点启用 AI 速度
   - 确认 PX4 能看到新的 ODOMETRY

6. 再注入 VIO/GPS 失效
   - PX4 pxh> failure vio off
   - 或关闭 GPS
   - 不应先失效再临时启动 AI 节点

7. 接管观察
   - listener estimator_status_flags
   - listener vehicle_local_position
   - 检查 cs_ev_vel、innovation、dead_reckoning
   - 检查速度、高度和姿态是否稳定

8. 立即结束测试
   - 测试时间只保留 10 至 20 秒
   - 主动降落
   - 不要在第一次接管测试中继续执行任务航点


10.4 常规分阶段测试
--------------------
1. 不上电机的台架测试
   - 静止放置
   - 检查修正 IMU 加速度
   - 检查静态校准
   - 检查静止输出速度是否接近零

2. SITL 链路测试
   - 使用普通 iris
   - 设置 EKF2_EV_CTRL=4
   - 关闭 GPS
   - 检查 MAVROS ODOMETRY 与 PX4 cs_ev_vel

3. 受控小幅运动
   - 检查速度正负号和坐标轴
   - 检查 1 m/s、2 m/s 等已知速度
   - 检查前后、左右、上下方向

4. 长时间测试
   - 观察速度漂移
   - 观察姿态漂移
   - 观察 EKF2 是否发生 inconsistent

5. 实机测试
   - 必须有安全员
   - 必须可立即切手动
   - 不得直接依赖该速度做长航时自主定位


十一、坐标轴
------------
默认将 MAVROS FLU 输入映射为模型使用的 [z, -y, x]：

  ai_imu_remap_mavros_axes:=true

如果实际硬件输入已经是模型坐标系，设置为：

  ai_imu_remap_mavros_axes:=false

上线前必须分别验证：

  - 加速度 x/y/z 方向
  - 角速度 x/y/z 方向
  - 积分后的世界速度方向


十二、常见问题
--------------
1. AI 节点日志一直显示 raw=0 Hz

   - 通常是没有启动 MAVROS。
   - 检查 /drone0/mavros/imu/data_raw 的 Publisher count。
   - 如果 Publisher count=0，说明只有 AI 订阅者，没有 IMU 发布者。
   - 使用完整 scenario_ros2.launch.py，并设置 use_mavros:=true。

2. 没有 /mavros/ai/imu_corrected

   - 检查 /drone0/mavros/imu/data_raw 是否有数据。
   - 检查 ONNX 窗口是否已经填满。
   - 等待至少 200 个输入样本。
   - 检查 onnxruntime 是否安装。

3. 没有 /mavros/odometry/out

   - 检查 use_ai_imu 是否为 true。
   - 检查 use_ai_imu_velocity 是否为 true。
   - 检查修正 IMU 是否发布。
   - 检查是否启用了两个冲突的 velocity 节点。

4. 静止速度不断增长

   - 启动时是否保持静止。
   - 启动时是否水平。
   - 等待静态校准完成。
   - 检查坐标轴映射。
   - 检查修正 IMU 静止加速度是否偏离重力方向。

5. PX4 没有融合速度

   - 检查 EKF2_EV_CTRL=4。
   - 检查 GPS 是否关闭。
   - 检查 MAVROS odometry 插件是否启用。
   - 检查 /mavros/odometry/out 的 frame_id 和 child_frame_id。
   - 检查消息时间戳是否持续更新。

十四、安全限制
--------------
本方案是实验性速度-only 观测。

它没有：
  - 绝对位置观测
  - 视觉回环
  - GPS 位置
  - 光流位置
  - 测距位置
  - 长期零偏稳定性保证

加速度和陀螺零偏、姿态误差、坐标轴错误都会造成速度漂移。

不要仅凭一次 SITL 成功就直接用于真实飞行。
正式使用前应由飞控/导航负责人复核状态估计、故障保护和失效策略。
