AI_IMU 修正 IMU + 速度观测接入 PX4 说明
========================================
更新时间：2026-11-04
适用环境：Ubuntu 22.04 + ROS 2 Humble
功能分支：feature/ai-imu-ros2
最新提交：d0ddbb7 Add experimental AI IMU velocity estimator


一、先明确“替代 VIO”的含义
----------------------------
当前方案不是用一个噪声协方差直接替代 VIO。

AI_IMU 模型输出：
  1. 修正后的加速度
  2. 修正后的角速度
  3. 加速度噪声/方差
  4. 角速度噪声/方差

速度节点使用修正后的加速度和角速度做捷联积分：

  角速度 -> 姿态积分
  加速度 -> 去重力 -> 世界坐标系速度积分

最终只向 PX4 提供速度观测，不提供可信位置。

因此这是“速度-only 外部导航”，不是完整 VIO。
长期运行会漂移，不能直接用于未经测试的实机自主飞行。


二、数据流
----------
原始 IMU：
  /drone0/mavros/imu/data_raw
  sensor_msgs/msg/Imu

AI 修正：
  /drone0/mavros/ai/imu_corrected
  sensor_msgs/msg/Imu

AI 噪声输出，可选监控：
  /drone0/mavros/ai/imu_noise
  ai_msgs/msg/ImuNoise

速度估计：
  /drone0/mavros/odometry/out
  nav_msgs/msg/Odometry

兼容速度话题：
  /drone0/ai_imu/velocity
  geometry_msgs/msg/Vector3Stamped

MAVROS 将 /mavros/odometry/out 转换为 MAVLink ODOMETRY，
PX4 再将其作为外部速度观测送入 EKF2。

--------
终端执行：

  cd /home/cjc/ws_capstone/gestelt
  source /opt/ros/humble/setup.bash

  python3 -m pip install --user -r \
    imu_listener_pkg/requirements.txt

  colcon build --symlink-install \
    --packages-select ai_msgs imu_listener_pkg

  source install/setup.bash

安装 Raynor SITL 模型和 airframe：

  ./gestelt_bringup/scripts/install_raynor_sitl.sh \
    /home/cjc/ws_capstone/PX4-Autopilot

  第一次安装后重新生成 SITL 目标：
  cd /home/cjc/ws_capstone/PX4-Autopilot
  DONT_RUN=1 make px4_sitl gazebo-classic_raynor

检查 ONNX Runtime：

  python3 -c \
    "import onnxruntime, numpy; \
     print(onnxruntime.__version__, numpy.__version__)"

注意：
  - 如果现有 NumPy 已经满足依赖，不要盲目升级或降级。
  - 当前环境已经验证 NumPy 1.26.4 和 2.2.6。
  - 某些 ROS 包依赖 NumPy 1.x ABI，较新的 OpenCV 又可能要求 NumPy 2.x。


四、PX4 设置
------------
本方案使用与 AI 模型数据域匹配的 Raynor SITL：

  cd /home/cjc/ws_capstone/PX4-Autopilot
  make px4_sitl gazebo-classic_raynor

等待：

  Ready for takeoff!

在 PX4 的 pxh> 终端执行：

  param set EKF2_EV_CTRL 4
  param set EKF2_GPS_CTRL 0
  param set EKF2_HGT_REF 0
  param save

参数含义：

  EKF2_EV_CTRL=4
    只使用外部 3D 速度观测。

  EKF2_GPS_CTRL=0
    不融合 GPS。

  EKF2_HGT_REF=0
    高度参考使用气压计。

EKF2_HGT_REF 是重启生效参数。保存参数后应重启 PX4。

如需测试故障保护：

  param set SYS_FAILURE_EN 1


五、启动 Gestelt、MAVROS 和 AI_IMU 速度节点
-------------------------------------------
终端 2：

  cd /home/cjc/ws_capstone/gestelt
  source /opt/ros/humble/setup.bash
  source install/setup.bash

  ros2 launch gestelt_bringup scenario_ros2.launch.py \
    scenario:=empty_map \
    run_mission:=false \
    use_rviz:=true \
    use_gazebo:=false \
    use_fake_drone:=false \
    use_mavros:=true \
    use_ai_imu:=true \
    use_ai_imu_velocity:=true \
    ai_imu_inference_stride:=1 \
    enforce_gps_off:=true

关键参数：

  use_ai_imu:=true
    启动 AI_IMU ONNX 修正节点。

  use_ai_imu_velocity:=true
    启动修正 IMU 速度节点。

  ai_imu_inference_stride:=1
    每帧都推理。当前机器约 1 ms/次，可接近 200 Hz。

  use_mavros:=true
    启动 MAVROS。速度 ODOMETRY 需要 MAVROS。

  enforce_gps_off:=true
    自动设置 EKF2_GPS_CTRL=0 并阻断 HIL_GPS。

不要同时设置：

  use_ai_velocity:=true

因为 use_ai_velocity 会启动另一个速度桥接节点，
造成两个发布者同时写 /drone0/mavros/odometry/out。

如果只启动 AI_IMU 包，也可以直接运行：

  ros2 launch imu_listener_pkg ai_imu_ros2.launch.py \
    namespace:=drone0 \
    enable_velocity_estimator:=true \
    inference_stride:=1


六、静止校准
------------
速度节点默认要求 200 个修正 IMU 样本用于静态校准：

  ai_imu_velocity_initialization_samples=200

校准内容：

  - 修正陀螺零偏
  - 修正残余重力/加速度偏置

校准期间速度保持为零。

输出频率约 200 Hz 时：
  200 个样本约 1 秒

默认推理 stride=5、输出约 40 Hz 时：
  200 个样本约 5 秒

启动条件：

  - 无人机必须静止。
  - 无人机必须水平放置。
  - 当前姿态积分从 identity 姿态开始。
  - 初始 yaw 无法仅靠加速度观测确定。

校准完成日志应出现：

  Stationary calibration complete: gyro_bias=[...]

校准完成前不要起飞。


七、检查 AI 修正数据
--------------------
检查修正 IMU：

  ros2 topic echo --once \
    /drone0/mavros/ai/imu_corrected

检查频率：

  ros2 topic hz /drone0/mavros/ai/imu_corrected

静止、水平放置时，修正后的加速度应接近：

  linear_acceleration:
    x: 接近 0
    y: 接近 0
    z: 接近 +9.81

注意：
  模型只有在 200 帧窗口填满后才发布修正 IMU。
  因此启动后不会立即出现 /mavros/ai/imu_corrected。


八、检查速度输出
----------------
只看线性速度：

  ros2 topic echo --once \
    /drone0/mavros/odometry/out \
    --field twist.twist.linear

检查频率：

  ros2 topic hz /drone0/mavros/odometry/out

检查兼容速度话题：

  ros2 topic echo --once /drone0/ai_imu/velocity
  ros2 topic hz /drone0/ai_imu/velocity

静止校准后的静止状态应接近：

  x: 0
  y: 0
  z: 0

Odometry 中：

  pose.position 为 NaN
  pose.covariance 很大
  twist.twist.linear 是有效速度
  twist.covariance 是速度协方差

这意味着 PX4 只能使用速度，不应把 pose 当成位置。


九、检查 MAVROS 和 PX4
----------------------
检查 MAVROS 输出：

  ros2 topic hz /drone0/mavros/odometry/out
  ros2 topic echo --once /drone0/mavros/odometry/out

在 PX4 pxh> 检查：

  listener estimator_status_flags
  listener vehicle_local_position
  listener vehicle_visual_odometry

重点确认：

  cs_gps: False
  cs_gps_hgt: False
  cs_ev_vel: True

没有 VIO 位置时，不要期待长期稳定的：

  cs_ev_pos: True
  cs_ev_hgt: True

速度-only 方案缺少绝对位置修正，因此位置会随时间漂移。


十、先起飞、中途失效的测试方法（直接输入模式）
------------------------------------------------
目标流程：

  VIO/GPS 正常
    -> AI_IMU 节点从启动开始直接发布速度
    -> VIO 和 AI 速度同时输入 PX4
    -> 正常起飞
    -> 注入 VIO/GPS 失效
    -> 保持 AI 速度观测
    -> 观察 EKF2
    -> 短时间测试后主动降落

本测试采用和之前 AI_IMU 节点相同的直接输入方式，不使用影子模式。

直接输入的含义：

  use_ai_imu_velocity:=true
    -> 自动启动 ai_imu_velocity.py
    -> 从启动开始直接发布 /drone0/mavros/odometry/out
    -> MAVROS 将速度转换成 MAVLink ODOMETRY
    -> PX4 与 VIO 一起融合

不能同时设置：

  use_ai_velocity:=true

否则会启动另一个速度桥接节点，产生重复发布者。

直接输入模式的风险：

  AI 速度在起飞前就已经进入 PX4 EKF2。
  如果 AI 速度在静止时漂移，会直接导致预飞失败。
  因此启动后必须先完成静止校准，并确认速度接近零。


10.1 直接输入模式启动流程
--------------------------
第一步：PX4 使用 VIO 正常运行。

  cd /home/cjc/ws_capstone/PX4-Autopilot
  make px4_sitl gazebo-classic_raynor

第二步：设置 PX4 同时使用 VIO 位置和 AI 速度。

  在 PX4 pxh> 执行：
    param set EKF2_EV_CTRL 15
    param set EKF2_GPS_CTRL 0
    param set EKF2_HGT_REF 3
    param save

  EKF2_EV_CTRL=15 表示外部视觉同时使用：
    - 水平位置
    - 高度
    - 3D 速度
    - yaw

  VIO 提供位置和高度，AI_IMU 提供速度。

第三步：启动 Gestelt、VIO、MAVROS 和 AI 速度节点。

  cd /home/cjc/ws_capstone/gestelt
  source /opt/ros/humble/setup.bash
  source install/setup.bash

  ros2 launch gestelt_bringup scenario_ros2.launch.py \
    scenario:=empty_map \
    run_mission:=false \
    use_gazebo:=false \
    use_fake_drone:=false \
    use_mavros:=true \
    use_ai_imu:=true \
    use_ai_imu_velocity:=true \
    enforce_gps_off:=true

启动后，不要另外运行 ai_imu_velocity.py。
use_ai_imu_velocity:=true 已经会自动启动该节点。

必须在起飞前保持静止。
等待 AI 速度节点日志出现：

  Stationary calibration complete: gyro_bias=[...]

第四步：确认 VIO 和 AI 速度同时被 PX4 使用。

  检查话题：
    ros2 topic hz /drone0/mavros/imu/data_raw
    ros2 topic hz /drone0/mavros/ai/imu_corrected
    ros2 topic hz /drone0/mavros/odometry/out

  检查 AI 速度：
    ros2 topic echo --once \
      /drone0/mavros/odometry/out \
      --field twist.twist.linear

  静止时应接近：
    x: 0
    y: 0
    z: 0

  在 PX4 pxh> 检查：
    listener estimator_status_flags

  起飞前应确认：
    cs_gps: False
    cs_ev_pos: True
    cs_ev_hgt: True
    cs_ev_vel: True
    cs_inertial_dead_reckoning: False

第五步：运行飞行脚本。

  飞行脚本文件：
    gestelt_bringup/src/scenarios/empty_map.py

  执行命令：
    cd /home/cjc/ws_capstone/gestelt
    source /opt/ros/humble/setup.bash
    source install/setup.bash

    先确认包能被找到：
    ros2 pkg prefix gestelt_bringup

    预期输出：
    /home/cjc/ws_capstone/gestelt/install/gestelt_bringup

    然后执行飞行脚本：
    python3 \
      "$(ros2 pkg prefix gestelt_bringup)/share/gestelt_bringup/scenarios/empty_map.py"

  不要在未 source 工作区的终端中从 ~ 目录直接执行该命令。
  否则 ros2 pkg prefix 会返回 Package not found，
  路径会错误地变成 /share/gestelt_bringup/scenarios/empty_map.py。

  也可以直接使用完整安装路径：
    python3 \
      /home/cjc/ws_capstone/gestelt/install/gestelt_bringup/share/gestelt_bringup/scenarios/empty_map.py

  直接路径方式仍然必须事先 source install/setup.bash，
  因为飞行脚本还需要导入 gestelt_msgs 和 gestelt_py_compat。

  empty_map.py 会执行：
    1. 将轨迹服务器切换到 HOVER
    2. 将轨迹服务器切换到 MISSION
    3. 发送航点 (2, 2, 2)
    4. 发送航点 (5, 5, 1)

  飞行脚本会执行 HOVER -> MISSION，并发送航点。
  如果只想先起飞悬停测试，不要运行 empty_map.py；
  待轨迹服务器进入 HOVER 后直接进行 VIO 失效测试。

  自动 run_mission:=true 不推荐，因为 launch 固定 3 秒后执行任务，
  可能早于 AI 窗口预热和静止校准。


10.2 飞行中手动断开 VIO
------------------------
直接输入模式下，VIO 和 AI 速度已经在起飞前同时工作。
飞到预定位置并稳定悬停后，可以手动断开 VIO：

  在 PX4 pxh> 执行：
    param set SYS_FAILURE_EN 1
    failure vio off

  手动恢复：
    failure vio ok

也可以通过 ROS 2 和 MAVROS 发送 Manual CommandLong：

  ros2 service call /drone0/mavros/cmd/command \
    mavros_msgs/srv/CommandLong \
    "{broadcast: false, command: 420, confirmation: 0, \
    param1: 6.0, param2: 1.0, \
    param3: 0.0, param4: 0.0, param5: 0.0, \
    param6: 0.0, param7: 0.0}"

恢复时把 param2 改为 0.0。

参数含义：
  command=420  MAV_CMD_INJECT_FAILURE
  param1=6     VIO
  param2=1     off
  param2=0     ok

断开 VIO 后，PX4 应继续使用 AI 外部速度。
如果 AI 速度没有被 EKF2 接受，PX4 会触发失效保护并盲降。


10.3 断开 VIO 后的观察与结束
------------------------------
1. 断开前检查
   listener estimator_status_flags

   应确认：
     cs_gps: False
     cs_ev_pos: True
     cs_ev_hgt: True
     cs_ev_vel: True
     cs_inertial_dead_reckoning: False

2. 悬停中断开 VIO
   failure vio off

3. 断开后立即检查
   listener estimator_status_flags
   listener vehicle_local_position

   预期变化：
     cs_ev_pos: False
     cs_ev_hgt: False
     cs_ev_vel: True

   如果 PX4 只能使用 AI 速度，水平位置会进入惯性推算，
   因此 dead_reckoning 可能变为 True，位置会逐渐漂移。

4. 检查 AI 速度是否继续发布
   ros2 topic hz /drone0/mavros/odometry/out
   ros2 topic echo --once \
     /drone0/mavros/odometry/out \
     --field twist.twist.linear

5. 检查 PX4 是否进入保护
   如果出现：
     cs_ev_vel: False
     local_velocity_invalid: True
     local_position_invalid: True
     Failsafe: blind land

   说明 AI 速度已经停止、时间戳过期、误差过大或被 EKF2 拒绝。
   PX4 触发盲降和自动上锁是正常失效保护。

6. 立即结束测试
   - 断开 VIO 后只观察 10 至 20 秒
   - 主动恢复 VIO 或主动降落
   - 不要在第一次测试中继续执行任务航点
   - 记录 ULog 中的 cs_ev_vel、innovation 和 failsafe


10.4 常规分阶段测试
--------------------
1. 不上电机的台架测试
   - 静止放置
   - 检查修正 IMU 加速度
   - 检查静态校准
   - 检查静止输出速度是否接近零

2. SITL 链路测试
   - 使用普通 iris
   - 设置 EKF2_EV_CTRL=4
   - 关闭 GPS
   - 检查 MAVROS ODOMETRY 与 PX4 cs_ev_vel

3. 受控小幅运动
   - 检查速度正负号和坐标轴
   - 检查 1 m/s、2 m/s 等已知速度
   - 检查前后、左右、上下方向

4. 长时间测试
   - 观察速度漂移
   - 观察姿态漂移
   - 观察 EKF2 是否发生 inconsistent

5. 实机测试
   - 必须有安全员
   - 必须可立即切手动
   - 不得直接依赖该速度做长航时自主定位


十一、坐标轴
------------
默认将 MAVROS FLU 输入映射为模型使用的 [z, -y, x]：

  ai_imu_remap_mavros_axes:=true

如果实际硬件输入已经是模型坐标系，设置为：

  ai_imu_remap_mavros_axes:=false

上线前必须分别验证：

  - 加速度 x/y/z 方向
  - 角速度 x/y/z 方向
  - 积分后的世界速度方向


十二、常见问题
--------------
1. AI 节点日志一直显示 raw=0 Hz

   - 通常是没有启动 MAVROS。
   - 检查 /drone0/mavros/imu/data_raw 的 Publisher count。
   - 如果 Publisher count=0，说明只有 AI 订阅者，没有 IMU 发布者。
   - 使用完整 scenario_ros2.launch.py，并设置 use_mavros:=true。

2. 没有 /mavros/ai/imu_corrected

   - 检查 /drone0/mavros/imu/data_raw 是否有数据。
   - 检查 ONNX 窗口是否已经填满。
   - 等待至少 200 个输入样本。
   - 检查 onnxruntime 是否安装。

3. 没有 /mavros/odometry/out

   - 检查 use_ai_imu 是否为 true。
   - 检查 use_ai_imu_velocity 是否为 true。
   - 检查修正 IMU 是否发布。
   - 检查是否启用了两个冲突的 velocity 节点。

4. 静止速度不断增长

   - 启动时是否保持静止。
   - 启动时是否水平。
   - 等待静态校准完成。
   - 检查坐标轴映射。
   - 检查修正 IMU 静止加速度是否偏离重力方向。

5. PX4 没有融合速度

   - 检查 EKF2_EV_CTRL=4。
   - 检查 GPS 是否关闭。
   - 检查 MAVROS odometry 插件是否启用。
   - 检查 /mavros/odometry/out 的 frame_id 和 child_frame_id。
   - 检查消息时间戳是否持续更新。

十四、安全限制
--------------
本方案是实验性速度-only 观测。

它没有：
  - 绝对位置观测
  - 视觉回环
  - GPS 位置
  - 光流位置
  - 测距位置
  - 长期零偏稳定性保证

加速度和陀螺零偏、姿态误差、坐标轴错误都会造成速度漂移。

不要仅凭一次 SITL 成功就直接用于真实飞行。
正式使用前应由飞控/导航负责人复核状态估计、故障保护和失效策略。
