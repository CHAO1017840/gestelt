五、准备 PX4 SITL 源码和依赖
----------------------------
如果 PX4 目录已经存在，跳过 git clone。

cd /home/cjc/ws_capstone
git clone https://github.com/PX4/PX4-Autopilot.git
cd PX4-Autopilot

切换到本次验证的提交：

git checkout 2110eae25d32ef102c5e44f2590fd7f9d65fc44d
git submodule update --init --recursive

安装 PX4 的 Ubuntu 依赖。只运行 SITL 时不需要 NuttX 交叉编译工具链：

cd /home/cjc/ws_capstone/PX4-Autopilot
bash Tools/setup/ubuntu.sh --no-nuttx

如果系统已经安装依赖，可以跳过这一步。

安装 MAVROS 的 GeographicLib 地理数据集：

sudo /opt/ros/humble/lib/mavros/install_geographiclib_datasets.sh

本机应存在：
/usr/share/GeographicLib/geoids/egm96-5.pgm


六、首次编译 PX4 SITL 和 Gazebo Classic 插件
--------------------------------------------
cd /home/cjc/ws_capstone/PX4-Autopilot
DONT_RUN=1 make px4_sitl gazebo-classic

DONT_RUN=1 表示只编译，不立即启动。
首次编译需要较长时间；以后再修改 PX4 时才需要重新编译。

编译完成后应先单独启动一次 PX4 SITL：

cd /home/cjc/ws_capstone/PX4-Autopilot
export GAZEBO_IP=127.0.0.1
export GAZEBO_MASTER_URI=http://127.0.0.1:11345
make px4_sitl gazebo-classic

该命令会同时启动：
1. PX4 SITL。
2. Gazebo Classic gzserver。
3. Gazebo Classic gzclient。
4. 具有真实动力学的 Iris 四旋翼。

必须优先把 Gazebo 绑定到本机回环地址。NUS VPN 或无线网卡可能使 Gazebo
通告 192.168.x.x，导致 GUI 的 scene 服务超时并出现黑屏。启动日志里的
“Publicized address”应为 127.0.0.1。

不要在这个流程中另外运行 Gestelt 的 gazebo_world.launch.py，
否则会出现第二个 Gazebo master，导致 gzserver 端口冲突或异常退出。


七、安装和编译 Gestelt
----------------------
cd /home/cjc/ws_capstone/gestelt
source /opt/ros/humble/setup.bash

首次使用时更新 rosdep。若提示已经初始化，可以跳过 sudo rosdep init：

sudo rosdep init
rosdep update

安装 package.xml 中声明的依赖：

rosdep install --from-paths . --ignore-src -r -y

完整编译：

colcon build --symlink-install

编译完成后加载工作空间：

source install/setup.bash

检查自定义包：

ros2 pkg prefix gestelt_bringup
ros2 pkg prefix gestelt_py_compat
ros2 pkg prefix gestelt_compat

正常输出分别位于：
/home/cjc/ws_capstone/gestelt/install/

检查包数量：

colcon list

当前应为 28 个 ROS 2 包。


八、修改后如何增量编译
----------------------
只修改 gestelt_bringup 的 launch、config、world 或场景资源时：

cd /home/cjc/ws_capstone/gestelt
source /opt/ros/humble/setup.bash
colcon build --symlink-install --packages-select gestelt_bringup
source install/setup.bash

修改以下公共内容时，必须完整编译：
1. gestelt_compat 或 gestelt_py_compat。
2. gestelt_msgs、gestelt_debug_msgs 或其他 .msg 文件。
3. trajectory_server 公共头文件。
4. navigator、grid_map 等被多个包依赖的接口。

完整编译命令：

cd /home/cjc/ws_capstone/gestelt
source /opt/ros/humble/setup.bash
colcon build --symlink-install --continue-on-error
source install/setup.bash


九、每个新终端的环境加载顺序
----------------------------
操作 Gestelt 的新终端都要执行：

cd /home/cjc/ws_capstone/gestelt
source /opt/ros/humble/setup.bash
source install/setup.bash

顺序不能反过来。必须先加载 ROS 2 Humble，再加载 Gestelt。

如果出现：
Package 'gestelt_bringup' not found

说明当前终端没有加载 install/setup.bash。

如果直接运行场景脚本时出现：
ModuleNotFoundError: No module named 'gestelt_py_compat'

同样说明当前终端没有加载 install/setup.bash。


十、VS Code Snap 和 RViz2 的 GTK 冲突
--------------------------------------
从 VS Code Snap 内置终端启动 RViz2 时，可能出现：
libpthread.so.0
undefined symbol: __libc_pthread_init
GLIBC_PRIVATE

使用 scenario_ros2.launch.py 的 use_rviz:=true 时，launch 会自动清理冲突变量。

手动启动 RViz2 时使用：

env -u GTK_PATH -u GTK_EXE_PREFIX -u GTK_IM_MODULE_FILE \
  -u GSETTINGS_SCHEMA_DIR -u GIO_MODULE_DIR -u SNAP_LIBRARY_PATH \
  rviz2 -d install/gestelt_bringup/share/gestelt_bringup/launch/rviz/gestelt_ros2.rviz
